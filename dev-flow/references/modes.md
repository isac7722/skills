# 진행 모드

`guided`가 기본이다. `yolo`는 검사·리뷰를 생략하는 모드가 아니라, 처음 합의한 성공 기준 안에서 후속 단계를 자동 진행하는 모드다. 모델·에이전트의 sandbox나 권한 플래그는 바꾸지 않는다.

| 시점 | guided | yolo |
|---|---|---|
| 조사·요구사항 결과 | 사용자 확인 | 설계와 함께 최초 승인 자료로 준비 |
| 설계·계획 결과 | 사용자 확인 | 성공 기준·계획·전달 범위를 한 번 확인 |
| 구현 결과 | 검증 진행 확인 | 자동 독립 검증 |
| 유효한 리뷰 지적 | 수정 착수와 수정 결과 확인 | 합의 범위 안의 수정·재검증 자동 |
| 모든 성공 기준 충족 | 전달 행동 확인 | 승인한 전달 방식 실행(기본 PR 초안) |

## 최초 yolo 승인

조사·설계 중 미정 사항은 질문한다. 다음 자료를 하나의 승인 대상으로 준비하고 `awaiting_confirmation`에서 실제 사용자 응답을 기다린다. “yolo로 해”라는 최초 요청이나 YAML 설정만으로 이 확인을 생략하지 않는다.

- 문제, 구현 범위와 제외 범위, 제품·설계 결정
- 관찰 가능한 성공 기준과 기준별 판정 방법
- 공개 테스트 경계, 검증 명령, 필요한 실행 환경
- 구현 계획, 역할·모델 배정, worktree·기준 커밋
- 자동 수정·독립 검증·로컬 커밋·푸시·PR 초안 게시까지의 진행 범위
- 대상 원격 저장소, PR base 브랜치, 전달 방식(`draft-pr` 기본, 명시적 `local`도 허용)

“이 성공 기준과 계획으로 구현·수정·검증 후 위 저장소에 PR 초안까지 자동 진행할까요?”라고 묻는다. 확인 응답과 승인 자료의 경로·해시·리비전·대상 저장소를 `decisions.md` 및 `state.yaml`의 `yolo_authorization`에 기록한다. 승인 전 상태는 null이다. 작업자가 자가 승인하거나 총괄이 사용자 응답을 만들어내지 않는다.

승인 후 각 단계 산출물을 계속 저장하고 진행 상황을 알리되 매 단계 응답을 기다리지 않는다. 구현물·테스트 결과의 정상 변화는 최초 승인을 무효화하지 않는다. 자동 전이는 승인 계약 ID와 결과 회차를 기록한다. 성공 기준을 충족하지 못한 상태를 검증 통과로 처리하거나 테스트 기대값을 느슨하게 바꿔 성공으로 만들지 않는다.

## 다시 판단받는 경우

- 범위·성공 기준·공개 테스트 경계·큰 설계 또는 PR 대상 변경
- 필수 검증 불가, 지정 에이전트 인증/실행 불가, 같은 원인으로 세 번 연속 진전 없는 실패
- 승인 이력과 맞지 않는 외부 파일 변경, 소유권 불명확, 추가 권한 필요

일반적인 구현·테스트 실패와 성공 기준 안의 리뷰 수정은 자동으로 처리한다. 막힌 원인과 선택지를 제시하고 `blocked` 또는 `awaiting_confirmation`으로 기록한다. 기준을 바꿀 경우 승인 계약의 새 리비전을 확인받는다. 병합·배포는 yolo 승인에 포함되지 않는다.

## 모드 변경과 재개

실행 시작 시 mode를 유효 설정에 저장한다. 기존 mode 없는 기록은 guided로 해석한다. 재개는 현재 YAML보다 저장된 mode와 승인 계약을 우선한다. 유효한 yolo 승인 이력이 없으면 자동 진행하지 않고 최초 확인을 수행한다.

진행 중 `guided → yolo` 요청에는 현재까지 확정한 결과를 포함해 남은 성공 기준·검증·전달 범위를 한 번 확인받는다. `yolo → guided` 요청은 즉시 이후 자동 배정을 멈추고 활성 작업 상태를 확인해 다음 경계부터 단계별 확인을 적용한다. 이미 수행한 외부 동작을 되돌렸다고 주장하지 않는다.
